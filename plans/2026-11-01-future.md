### Terms

We need a pipeline like this.

There are a few static variables defined in config (.env / .env.local)

- IterationCount is decided based on how long the process of creating a new _Song_ takes. I.e. how many _Iterations_ does the UI need to roll through while the backend is producing a new _Song_.
- VariationCount defines how many variations are cycled through the Iterations.
- MoodCount defines how many _Moods_ are cycled through within a _Song_

The _Never Ending Song_ is a dual loop, where the _Song_ is generated programmatically by repeating the following steps in the server side and simultaneously replayed in time in the client side. The Iterations that the client side loop is replaying are always already generated at by the server side just in time (defined by IterationCount).

1. _Moods_ are outlined (let's say randomly for now) as a verbal decriptions of a few words. E.g. "70s psychedelic funk" + "piano ballad"
2. _Melody_ is decided with _Moods_ as the input (defines major/minor, tonal characteristics etc). N voices can be used to form a choir. N _Variations_ are generated for _Melody_ to ensure slight variance.
3. _Lyrics_ (which later refine the concrete rhythm of _Melody_) are generated with _Moods_ and previous _Lyrics_ (if not first _Iteration_) as the input.
4. _Singers_ are decided (let's say randomly for now). The vocal characteristics that can be used to vary the voices produced by Chimera.
5. _Song_ is composed from _Lyrics_, _Melody_, _Mood_, _IterationCount_. The product should be the composition written down in the Chimera input json language, each _Iteration_ locked down to the note.
6. _Vocals_ are recorded with just the singing produced with Chimera. _Vocals_ recording should have some humanization to keep _Iterations_ slightly varying.
7. _Music_ is generated with _Mood_ and _Vocals_ as input. As before, _Music_ consists of the background accompanying the _Vocals_

Final output is _Music_ and _Vocals_, pieced together in the UI timed along with the _Lyrics_.

Chimera is a program, so we build and run it. The AI models we use are

- The existing model for Music (newer version probably does not exist). It has perfect weirdness which does not exist in 2026-era music models
- A local model that fits 12GB VRAM for lyrics instead of GPT. Linux server side. Python or Bun. We'll conserve GPU by loading Lyrics model and Music model separately.
