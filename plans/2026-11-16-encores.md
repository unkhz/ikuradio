# Encores

When the Archive has no new Song to announce, the Radio goes quiet. `listen` in `packages/radio/index.ts` finds nothing and returns. The page says the song holds its breath, and after `grace` (fifteen minutes) `pulse` says the heart has stopped. That gap should be filled.

An encore is a rerun of a set of Songs already in the Archive, announced by the Tactus the same way a new Song is: a beginning, a length, the same moment on every Receiver. It is not a new Session, and it does not add a Song to the Archive.

The Tactus declares a mode. For now it is `live` or `encore`. An encore being aired is mode `encore`. The live show is mode `live`. Hearing a Song again on its page, `/s/<id>/<slug>`, is neither: the Tactus is not declaring it.

When a new Song can be played again, the Tactus enqueues the live show. The encore being aired is not stopped. The live show begins only after that Song has ended.

## When it starts

The first reason is a missing new Song: `nextPlayable` has nothing to announce. Other reasons can start the same mode later, and are not built here.

While a new Song is missing, the mode is `encore`, and encores are aired one after another. One already announced plays to its end. The Tactus does not move a beginning once it has been told. When a new Song is in the Archive and can be played, the live show is enqueued after that ending, and the mode returns to `live`.

If the page cannot reach `/tactus`, it stays quiet, as it does now (`~ the radio is quiet ~`). The page does not keep a playlist of its own. The Tactus is what starts an encore, the same way it starts a Song.

## Setups

There can be more than one way to choose what is rerun. The first, and the only one built here, is **Favourites**.

Favourites rotates the critic's favourites. Today the only file is `critic/scientist.json`, committed, and read by the Studio. Nothing generated is written into `critic/`. Other sources can be added later, and are not built here. If that file names no Song the Archive can play, there is no encore, and the gap stays.

The file lists favourites under each part, a Song (`1`) or one section of a Song (`"45:3"`). An encore plays the Song, not the section. A section counts as its Song. A Song named more than once is played once per turn of the list. They are played in turn, and when the list ends it begins again. The file is three lists, not one playlist, so the order they are flattened into is open.

The Radio remembers which favourite played last from the announcements it already journals in `memory/tactus.jsonl`, so a restart does not always begin at the first.

## The tag

While an encore is being aired, the mode is `encore`, and the page shows an encore tag, so a rerun is not mistaken for a new Song. Mode `live` does not show it. The Song's page does not show it. Where on the page the tag sits is open.

`/tactus` tells the page the mode, and, when it is `encore`, the setup. The page cannot invent either. `told` today sends the Song, its Session, the Archive, the beginning and the length, and nothing else.

## What stays

- A lost `/tactus` is still silence. An encore does not paper over it.
- A beginning, once told, does not move.
- `critic/scientist.json` stays hand-written. The Radio only reads it.
- The Song's page and autoplay are unchanged. They follow Songs that have aired, not the encore playlist.

## What moves

- `radio`: the Tactus declares a mode, `live` or `encore`. When no new Song can be announced, the mode is `encore`, and the next favourite is announced and journaled with the others. What is announced carries the mode, and, in `encore`, the setup.
- `archive` is not written. The Session played is the one already there.
- `ui`: the encore tag, from the mode `/tactus` declares, only while an encore is being aired.

## Order of work

1. The Tactus declares a mode, `live` or `encore`, and `/tactus` tells the page. An encore also names the setup.
2. Favourites: the Songs named in `critic/scientist.json`, each once, rotated, the place taken from the journal.
3. `listen` sets the mode to `encore` and announces the next favourite when no new Song is waiting. When a new Song can be played, it enqueues the live show after the encore being aired has ended, and the mode returns to `live`.
4. The page shows the tag only while an encore is being aired.

## Done when

- With no new Song in the Archive, an encore is aired, the mode is `encore`, the tag is visible, and the next favourite follows when it ends.
- When a new Song can be played, the live show is enqueued after the encore being aired has ended, and the tag is not shown once the mode is `live`.
- A second pass through the favourites plays them again, and a restart does not always begin at the first.
- With no favourite the Archive can play, nothing is aired, as now.
- With no connection to `/tactus`, the page is quiet, and does not play an encore of its own.
- The Song's page shows no encore tag.
